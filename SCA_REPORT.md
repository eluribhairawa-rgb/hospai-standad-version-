## Exposure assessment

- **`vite` and `esbuild`** are build-time / development tools; `nanoid` and `source-map-js` are transitive packages that, as far as the audit data shows, are not direct runtime code of the app. They are used
  inside the Docker *build* stage; the production image only contains the compiled static files,
  so these issues do not run in the deployed application. They matter for developers running
  `npm run dev` on a networked machine.
- **`jspdf` / `dompurify`** ship to the browser. jsPDF is used to build PDFs from data generated by
  the application itself (dashboard/report exports), not from arbitrary third-party input, which
  limits practical exploitability. Treat the critical rating as real but lower-likelihood, and
  schedule the upgrade.

## Recommended remediation (in priority order)

1. `cd frontend && npm audit fix` – clears `nanoid` and `source-map-js` with no breaking changes.
   Commit `package.json` **and** `package-lock.json` together.
2. Upgrade `jspdf` to ≥ 4.2.1 (major). Re-test every client-side PDF path
   (`src/lib/exportService.ts`: dashboard, billing and report exports) and the footer/logo drawing.
3. Upgrade `vite` (and its plugin) to a patched major in a separate change; run `npm run build`
   and a full UI smoke test. Until then, do not expose the Vite dev server beyond localhost.
4. Add this scan to CI so each pull request fails on new High/Critical findings:
   `npm audit --audit-level=high` for the frontend and an OSV/pip-audit step for `requirements.txt`.

## Limitations
